# T4 네트워크 사전검토

## 기획의 범위와 완료 조건

원문 범위: VPC, 서브넷 6개, IGW/NAT, SG 4종, SSM용 IAM/엔드포인트, S3 백엔드.
원문 T4 완료 조건: terraform validate + plan 리뷰 통과.
이 스킬은 그 전의 읽기 전용 사전검토다. Terraform 코드를 만들거나 init/plan을 실행하지 않는다.

## 담당·입력

메인이 infra-reviewer와 docs-auditor 중 필요한 역할에 읽기 전용 검토를 요청한다.
plan-aws.md, AI_RULES.md, docs/design-aws.md, docs/design.md, 확정 ADR/가정,
현재 infra/와 T0 결정 표·T3 후속 보고·기존 T4 승인 기록을 읽는다.
T3 최종 증거가 유효하면 30분 소크를 자동 재실행하지 않는다.

## 확인 절차

1. T0 D1~D6의 권고와 확정을 구분한다. 계정/리전/2AZ/CIDR/태그/기존 상태 저장소 등
   코드에 필요한 실제 입력을 현재 저장소에서 찾고, 없는 값만 사람에게 요청한다.
2. ‘SG 4종’과 §1에 나열된 sender/int-alb/ext-alb/receiver/db 5종의 차이를 확인한다.
   이미 정정됐으면 다시 미결로 만들지 않는다. Endpoint 전용 SG는 제안이지 자동 확정이 아니다.
3. 서비스 체인을 표로 만든다: sender→내부ALB:443, 내부/외부ALB→receiver:3000,
   receiver→DB:5432. 외부 ALB는 승인 CIDR에서 443만 허용하는 후속 T9 경로다.
4. SSM Agent/로그/패키지 다운로드에 필요한 별도 egress와 Endpoint inbound를 정리한다.
   receiver 5432-only, DB egress 없음과 무SSH/SSM 운영의 충돌이 해결됐는지 확인한다.
   정확한 Endpoint 서비스/유형/AZ/DNS/SG/IAM·정책을 제안하되 무조건 다 추가하지 않는다.
5. 공개2/앱2/데이터2 서브넷과 라우트 연결을 정리한다.
   데이터 서브넷에는 인터넷 기본 경로가 없다. DB PG16·Agent·chrony 공급 방식이
   이 조건과 양립하는지 확인하고 미확정이면 선택지/승인 필요사항으로 남긴다.
6. 기존 S3 backend의 존재·접근·잠금 방식을 확인한다. 없으면 bootstrap과 런타임 분리안을 제시한다.
   최초 상태 버킷 생성은 사람 apply, 기존 상태 자동 이동·폐기 금지.
   Terraform 버전에 맞는 잠금 방식을 검토하고 기존 구성을 조용히 바꾸지 않는다.
7. 시크릿은 SSM 이름/ARN·IAM만 Terraform에 두고 실제값은 runtime에서 주입하는 경계를 확인한다.
8. NAT 단일 AZ·Endpoint 수×AZ·상태 S3 등의 비용 항목을 정리한다. 확인 못 한 단가를 확정치로 쓰지 않는다.
9. T4 구현 예정 파일과 후속 출력(VPC/subnet/SG/route/Endpoint/IAM 식별자)을 제시한다.
   EC2/PG/user_data/ALB 본체/ACM/Route53/대시보드는 이번 구현에서 제외한다.
10. T5의 receiver psql 검증은 T6 생성에 의존하며, T8의 최초 준비/15분 재현 범위도
    사람 결정이 필요할 수 있음을 후속 인계한다.

## 첫 응답 — 여기서 멈춘다

확정 범위 / 충돌·누락(파일·절) / SG·라우트·Endpoint 표 / 변경 예정 파일 /
비용 항목 / 사람 결정 목록 / T3 인수 상태를 보고한다.
읽기 전용 검토 완료를 T4 전체 완료로 보고하지 않는다.
사람이 결정과 문서 정리를 승인한 뒤 별도 요청으로 infra-developer에게 T4 구현을 맡긴다.

## 공통 실행 경계 — 스킬 호출이 권한을 확대하지 않는다

- 적용되는 AGENTS.md/하위 지침과 AI_RULES.md를 우선 확인한다. 현재 요청이 허용한 단계·파일만 다룬다.
- 먼저 git 브랜치/HEAD/status와 기존 변경·실행 프로세스를 확인한다. 기존 수정·데이터·증거를 보존한다.
- 메인이 작업을 조율하고 작성자는 동시에 1명만 둔다. 리뷰어는 파일/테스트를 수정하지 않는다.
  이 스킬을 읽었다고 에이전트가 자동 생성되는 것은 아니다. 실제 위임할 때 역할·경로·검증 범위를 전달한다.
- terraform apply/destroy는 사람이 실행한다. CLI/SDK/terraform test/provisioner로 우회하지 않는다.
  자격 증명·backend·입력 부재를 가짜 값으로 메우지 않는다. 운영 대상 변경은 별도 승인 없이는 하지 않는다.
- 시크릿 값은 조회·출력·커밋하지 않는다. 인스턴스 runtime 주입용 코드는 이름/ARN과 IAM만 다룬다.
- DB 초기화·부하·서비스 중단은 정확한 계정/환경/대상/범위와 복구 계획에 대한 명시적 승인 후에만 한다.
- 단계 표의 완료 조건을 임의 완화하지 않는다. 읽기/코드 작성/정적 검증/plan 리뷰/사람 apply/실측을 분리한다.
- 근거는 현재 저장소와 실행 로그다. 오래된 첨부본으로 최신 T3 보고·design-aws.md를 덮어쓰지 않는다.
- 결과는 PASS/FAIL/BLOCKED/NOT_RUN으로 구분한다. 실행한 명령·종료 코드·시각·버전·증거 경로를 적는다.
- 원래 과제/기획과 충돌하는 안전상 보강·새 선택은 제안으로 표시하고 사람이 기준 문서를 정리하기 전 강행하지 않는다.
- 별도 요청 없이 git add/commit/push나 브랜치 조작을 하지 않는다.
